설비 Down 뒤, 무엇이 먼저 깨졌나

수만 줄의 설비 로그에서 알람을 발생 단위로 묶고, 알람 앞에 반복된 경고와 경고→알람 리드 타임을 통계로 찾아, 근거 줄이 붙은 원인 후보를 보여줍니다. 파일은 이 브라우저 밖으로 나가지 않습니다.

  1. 1로그 불러오기
  2. 2알람 군집 · 타임라인
  3. 3직전 경고 · 리드 타임 · 원인 후보
  4. 4현장 검증 (재현 → 비교 → Shadow → 전환)

로그 불러오기

로그 파일을 이 페이지에 끌어다 놓아도 됩니다

읽기 설정 (형식 · 인코딩 · 시간대)
비우면 머리글 이름(time · level · module · message 등)으로 찾습니다. 번호는 1부터, 날짜와 시각이 다른 열이면 1+2.

예: 2026-11-10 09:12:40.000 ALARM [LOADER] L103 Wafer vacuum lost

내보내기

타임라인 드래그로 확대 · 더블클릭으로 전체 · 알람을 누르면 해당 군집으로 · 키보드: ← → + − 0

정보 밀도경고알람선택한 군집의 발생

알람 군집 첫 알람이 같은 발생끼리

    현장 검증 절차 바꾸기 전에 같은 데이터로 확인하고, 새 방법은 옆에서 먼저 돌려 보고, 언제든 되돌립니다

    로그

    합성 로그: 가상 검사기 SpotCheck 의 하루 (실제 장비 · 알람 코드와 무관). 데이터는 이 기기에만 저장됩니다.

    설정

    LLM (선택 사항 — 없어도 모든 기능이 규칙으로 동작)
    브라우저에서 부르려면 Ollama 에 이 페이지 주소를 허용해야 합니다 (OLLAMA_ORIGINS). 도움말 FAQ 참고.
    보내기 전 마스킹
    데이터
    저장 위치: 이 브라우저의 IndexedDB (사례 · 규칙 · 설정 이력 · Shadow 기록 · 마지막 파일). 서버로 보내지 않습니다.
